# Design: v1.2 Same-home cross-process locks

**Date:** 2026-10-31  
**Status:** Approved (user chose same home)  
**Scope:** Pain point 5 — safe concurrent MCP clients sharing one runner home.

## Decision

- **Same home by default:** `~/.java-project-runner` shared by Cursor, Claude Code, etc.
- **Cross-process per-project file locks** on mutating ops so two MCP processes cannot start/stop/build the same project concurrently.
- Optional `JAVA_PROJECT_RUNNER_HOME` absolute path overrides the home root (escape hatch; default remains same-home).

## Locking

- Lock files: `<runnerHome>/locks/<projectId>.lock` (touch file + `proper-lockfile`).
- Wrap existing `projectMutex.runExclusive` so in-process + cross-process both apply.
- Fail fast → `BUSY` (minimal/no retries) when another process holds the lock.
- Covered ops: build, start, stop, restart, reclaim, force_stop (already via `runExclusive`).
- Registry JSON already file-locked; unchanged.

## Docs / version

- README: same-home is supported with locks; remove “do not run multiple servers”.
- Note optional `JAVA_PROJECT_RUNNER_HOME`.
- Bump to `1.2.0`.
